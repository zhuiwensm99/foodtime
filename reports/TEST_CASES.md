## 一、概述与测试环境

### 1.1 项目简介
食光（foodtime-xianzhi）是一款面向家庭冰箱/食材管理的 Web 应用，包含：
- **前端**：原生 JS（`public/app.js`、`public/index.html`、`public/styles.css`、`public/styles-foodtime.css`），无框架 SPA，通过 `setView(view)` + `data-view-panel` 切换视图。
- **后端**：Node 原生 `http`（`src/server.js`），`routeApi` 统一处理 `/api/` 请求，使用 `better-sqlite3`（本地开发）/ Blob（EdgeOne 部署）持久化。
- **领域服务**：`src/foods.js`、`src/activities.js`、`src/domain.js`、`src/households.js`、`src/auth.js`、`src/recipes.js`、`src/alerts.js`、`src/ai.js`、`src/agent.js`。

### 1.2 测试环境
| 项 | 值 |
|---|---|
| 前端预览地址 | http://127.0.0.1:8790/ |
| 后端 API 基址 | http://127.0.0.1:8790/api/ |
| 测试账号 | `admin` / `fridge-demo` |
| Node 版本 | ≥ 22.5 |
| 数据库 | 本地 `better-sqlite3`（首次启动自动迁移建表） |
| 探测工具 | `curl --noproxy '*'`（禁用代理，避免误走线上） |

### 1.3 前端视图（data-view-panel）清单
登录后共 15 个面板：`home`(首页)、`display`(全屏展示)、`items`(库存)、`ledger`(台账)、`alerts`(预警)、`account`(账户管理)、`agent-settings`(Agent 设置)、`preferences`(偏好设置)、`agent`(物品助手)、`ledger-list`(台账明细)、`recipes`(菜谱)、`recipes-detail`(菜谱详情)、`notifications`(通知)。
> 注：`setView` 中 `VIEW_ALIASES = { household: "account" }`，深链 `#/household` 会映射到账户管理；`views` 集合中**不含** `member`/`household`，调用将回退首页。

### 1.4 用例字段约定
每条用例包含：**用例编号、所属模块、功能点、前置条件、操作步骤、预期结果、实际结果（留空待填）、优先级（P0/P1/P2）、是否涉及死页/空页面检查**。

### 1.5 优先级定义
- **P0**：核心流程、阻断性功能、死页/崩溃、登录与数据写读。
- **P1**：重要交互、错误处理、鉴权越权、空状态展示。
- **P2**：次要交互、边界值、体验优化项、已知 P3 缺陷的回归点。

## 二、用例设计原则

1. **逐个功能点**：每一个 `data-view-target`、导航项、按钮、tab、弹窗、表单提交都需至少一条用例。
2. **每个点击都有响应**：任何可点击元素都必须有可观测的页面跳转、状态变化或提示，不允许“点击无反应”。
3. **死页/空页面专项（重点）**：
   - 空列表（无食材、无活动、无菜品、无通知、无会话、无令牌）必须展示明确的**空状态文案/插画**，不得白屏或仅显示标题。
   - 深链/非法视图必须**安全回退**到首页或已有面板，不得卡死或空白。
   - 已知缺口（审计 P3-6 全屏展示区块元素缺失、P3-7 缺复制邀请按钮、P3-8 `renderMember` 死代码）需作为**反向/边界用例**登记，验证“不崩溃、有兜底”。
4. **后端异常覆盖**：参数缺失、类型错误、未授权（401）、越权（403/409）、资源不存在（404）、批量边界（1–25 个 ID）、枚举非法值。
5. **实际结果栏**保持空白，由执行人填写；文档只固化“预期结果”。

### 3.13 家庭成员邀请闭环（INV-001 ~ INV-007）

> 闭环目标：账户页生成一次性邀请码 → 提供「复制邀请码」「复制注册链接」 → 受邀人打开 `?invite=CODE` 链接自动进入注册并回填邀请码 → 提交后加入邀请方家庭；重复/无效邀请码被拒。

**INV-001｜账户｜生成邀请码与展示** 〔P0〕

- 步骤：1. 进入账户页；2. 点击「生成邀请码」（`#createHouseholdInvite`）。
- 预期：展示邀请码（`#householdInviteCode`）、有效期说明（`#householdInviteExpires`），分享面板（`#householdInvitePanel`）可见。
- 实际：
- 优先级：P0｜死页检查：否

**INV-002｜账户｜复制邀请码 / 注册链接按钮** 〔P0〕

- 步骤：1. 点击「复制邀请码」（`#copyHouseholdInviteCode`）；2. 点击「复制注册链接」（`#copyHouseholdInvite`）。
- 预期：两个按钮均存在且可点击；点击后触发复制并给出反馈（toast）。
- 实际：
- 优先级：P0｜死页检查：否

**INV-003｜注册｜邀请链接自动回填** 〔P0〕
- 前置：未登录，浏览器打开 `http://127.0.0.1:8790/?invite=<CODE>`。

- 预期：自动切换到注册模式（`#registerForm` 可见），且「邀请码（可选）」输入框（`#registerInvitationCode`）已填入 CODE；无需手动粘贴。
- 实际：
- 优先级：P0｜死页检查：否

**INV-004｜注册｜用邀请码注册加入家庭** 〔P0〕
